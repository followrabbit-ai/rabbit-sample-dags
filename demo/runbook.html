00The one message the video has to land

Everything else is scaffolding for this:

Through-line

“Rabbit is a drop-in — the same adapter for dbt, the same plugin for Airflow. Your SQL, models, and DAGs don’t change. Every BigQuery job gets routed to whichever is cheaper for that job: on-demand or your reservation. You turn it on with a profile change or a plugin install, plus one reservation ID.”

Both chapters follow the same three-beat arc so the pattern is unmistakable: (1) show the integration is tiny and non-invasive, (2) run a workload with optimization off and then on so the log lines change on screen, (3) cut to the Rabbit dashboard to see the routed jobs and the savings.

Non-negotiable

The optimizer is a silent no-op when reservation_ids is empty — in both tools. The "off vs on" beat is exactly this toggle. Rehearse it; it's the most convincing 30 seconds in the video.

01Production phases

Record out of order. Chapters 1 and 2 are the hard part — do them first, while the environment is warm, then bookend with the intro and close once you know what you actually said.

  1. Pre-flight (§02) — provision-check the environment, pre-bake every slow step, stage the repos and browser tabs.
  2. Capture setup (§03) — resolution, fonts, secret hygiene, notifications off, one clean shell.
  3. Record Chapter 1 — dbt (§05) — in 6–8 short takes, one per beat. Re-record a beat, not the whole chapter.
  4. Record Chapter 2 — Airflow (§06) — same, 6–8 takes.
  5. Record cold open + close (§04, §07) — last, scripted, to camera or over a static repo view.
  6. Edit & publish (§08) — assemble, add on-screen callouts for the log lines, chapter markers, scrub for leaked secrets, write the description.
Why takes, not one pass

A live dbt build against public data is 30–90s of dead air. Record each beat separately, cut the waiting in the edit, and narrate the result over a still frame. Nobody wants to watch a spinner.

02Environment pre-flight

You said the environment is fully provisioned. Confirm each piece is live the morning of the recording — tokens expire, reservations get deleted, Composer environments get paused.

Checklist

  • GCP project with BigQuery enabled, and you know its ID. Used as $GCP_PROJECT.
  • A BigQuery reservation in the recording region, ID in the form project:US.reservation-name. This is $RESERVATION_ID — without it, nothing routes.
  • Rabbit tenant + API key from app.followrabbit.ai/api-keys, exported as RABBIT_API_KEY in a file you never show.
  • Datasets exist: dbt_demo (dbt) and airflow_demo (Airflow), plus the GCS export bucket for the DAGs.
  • Composer 3 environment running, name + region known ($ENV / $LOC), with the plugin already installed (see below).
  • ADC login fresh: gcloud auth application-default login done today; gcloud auth login too.
  • dbt venv built and working: dbt debug passes green.
  • Recent public data — the sample models pull a rolling 30-day window off max(start_time), so they self-adjust; just confirm a build produces non-empty marts.

Pre-bake the slow steps (do these the day before)

Installing the Airflow plugin rebuilds the Composer image and takes 15–25 minutes. Never do this on camera. Run it ahead of time so §06 opens with the plugin already live:

run the day before recordinglocal shell · gcloud
# one-off manual install — rebuilds the env image, 15–25 min
gcloud composer environments update "$ENV" --location "$LOC" \
    --update-pypi-packages-from-file=requirements-composer.txt

Also pre-stage: a completed successful DAG run in history (so "here's one from earlier" is available if a live trigger stalls), and the Rabbit dashboard already showing some routed jobs.

Stage on the desktop

  • dbt-rabbit-samples open in the editor — README.md, profiles.sample.yml, a model file, .github/workflows/release.yml.
  • rabbit-sample-dags open — README.md, requirements-composer.txt, dags/bigquery_elt_demo.py.
  • Browser tabs, in order: Rabbit Dynamic Pricing dashboard, the Airflow UI, the BigQuery console on $GCP_PROJECT.
  • A terminal, one tab, in the dbt repo, venv activated, $GCP_PROJECT / $RESERVATION_ID / $ENV / $LOC exported, RABBIT_API_KEY sourced from a hidden file.

03Capture setup

  • Record at 1920×1080 (or 2560×1440 downscaled). Set the display scaling before you open anything.
  • Terminal font ≥ 18pt, editor font ≥ 16pt. Readability on a phone is the bar.
  • Minimal shell prompt — no long path, no git branch spew. Something like demo $.
  • Notifications off — macOS Focus / Do Not Disturb, quit Slack and Mail, silence calendar alerts.
  • Secret hygiene: keep RABBIT_API_KEY in ~/.rabbit.env and source it before recording. Never echo $RABBIT_API_KEY, never cat the file, never open profiles.yml with a real key. Clear scrollback (clear && printf '\033[3J') between takes.
  • Redact in the DAG connection step: type the connections add command with $RABBIT_API_KEY as the literal variable, not the value — or blur it in post.
  • Cursor emphasis / keystroke overlay on if your recorder supports it (OBS, ScreenFlow, CleanShot).
  • Talk ~15% slower than feels natural. Pause between commands so the edit has clean cut points.
  • Separate audio track if you can — re-recording VO is easier than re-recording screen.

04Cold open — record last, ~60s

Script beat

“BigQuery gives you two ways to pay: on-demand, per byte scanned, or slot-based capacity you reserve. The cheapest choice changes job by job — and picking per job by hand isn't realistic. The Rabbit Pricing Model Optimizer makes that choice automatically, at query time. In the next 15 minutes I'll turn it on two ways: first in a dbt project, then in an Airflow pipeline on Cloud Composer. Same optimizer, and in both cases the transformation code doesn't change at all.”

On screen: the two repo READMEs side by side, or a one-slide title card. Keep it moving — get to the terminal fast.

05Chapter 1 — dbt (~6 min)

Repo: dbt-rabbit-samples. Two BigQuery ELT pipelines (bikeshare, bitcoin_cash), each staging → mart. The adapter dbt-rabbit-bigquery replaces dbt-bigquery.

screen profiles.sample.yml in the editor

Then open a model — models/bikeshare/staging/stg_bikeshare_trips.sql — and say "this doesn't change, and neither does anything else in models/."

say

“It's a superset of the standard adapter. Same connection, same models, same tests — plus these three keys.”

2:00

Baseline — optimization OFF

screen terminal, then logs/dbt.log

With RABBIT_RESERVATION_IDS unset, run one pipeline. Call out that the build fully succeeds — Rabbit fails safe to plain BigQuery.

chapter 1 · baselinedbt repo
unset RABBIT_RESERVATION_IDS
dbt build --select bikeshare

  Missing required rabbit_reservation_ids

say

“No reservation, so it does nothing — and nothing breaks. The pipeline runs exactly as it did before Rabbit.”

3:15

Flip it ON

screen terminal, then logs/dbt.log

chapter 1 · enabledbt repo
export RABBIT_RESERVATION_IDS="your-project:US.your-reservation"

dbt build --select bikeshare --debug

# now in logs/dbt.log:
RabbitBigQuery adapter: Rabbit optimization enabled
RabbitBigQuery adapter: routing job ... pricing_mode=...

Run grep RabbitBigQuery logs/dbt.log to isolate the routing lines. This is the "it's working" proof for dbt.

4:30

The payoff — Rabbit dashboard

screen browser · Dynamic Pricing tab

Show the jobs from this dbt build appearing, the pricing decision per job, and the savings figure. Note there's a short lag — this is why you pre-staged earlier runs.

5:15

Productionizing (brief)

screen profiles.docker.yml, .github/workflows/release.yml

06Chapter 2 — Airflow / Composer (~6 min)

Repo: rabbit-sample-dags. Same two ELT pipelines as DAGs on Managed Service for Apache Airflow (Composer 3). The optimizer is an Airflow plugin that patches BigQueryHook at startup — the DAG code is untouched.

0:00

Two PyPI packages, zero DAG changes

screen requirements-composer.txt, then dags/bigquery_elt_demo.py

Show the two pins: rabbit-bq-job-optimizer (client) and rabbit-bq-optimizer-airflow-plugin (the plugin). Then scroll the DAG — three BigQueryInsertJobOperator / BigQueryToGCSOperator tasks, no Rabbit imports anywhere.

say

“Airflow discovers the plugin through its entry point. At startup it wraps BigQueryHook, so every BigQuery job any DAG submits goes through Rabbit first.”

1:15

The plugin is already installed

screen terminal (show the command, note it's pre-run), then Airflow UI → Admin → Plugins

chapter 2 · install — PRE-RUN, do not run live (15–25 min)local shell · gcloud
gcloud composer environments update "$ENV" --location "$LOC" \
    --update-pypi-packages-from-file=requirements-composer.txt

Cut to Admin → Plugins and point at the Rabbit BQ Optimizer row. That's the proof it registered.

2:15

Connection + config variable

screen terminal

The API key lives only in the Airflow connection — not in the repo, not in GitHub. Operators set it per environment.

chapter 2 · configurelocal shell · gcloud composer
gcloud composer environments run "$ENV" --location "$LOC" \
    connections -- add rabbit_api \
    --conn-type generic \
    --conn-password "$RABBIT_API_KEY" \
    --conn-extra '{"api_base_url":"https://api.followrabbit.ai/bq-job-optimizer"}'

gcloud composer environments run "$ENV" --location "$LOC" \
    variables -- set rabbit_bq_optimizer_config \
    '{"default_pricing_mode":"on_demand","reservation_ids":["YOUR_PROJECT:US.YOUR_RESERVATION"]}'
watch

Type $RABBIT_API_KEY as the variable — don't paste the value on screen. Same silent-no-op rule: an empty reservation_ids list means the plugin skips optimization and you get a warning in the task log instead of a result.

3:30

    dags trigger -- bigquery_elt_demo

Switch to the Airflow UI, watch stage_trips → aggregate_daily_rides → export_to_gcs go green. (Cut the wait in the edit.)

08Edit & publish

  • Assemble in take order: cold open → dbt beats → Airflow beats → close.
  • Cut the dead air — every dbt build spinner, every DAG wait. Narrate results over a frozen frame.
  • On-screen callouts highlighting the key log lines: Rabbit optimization disabled, Rabbit optimization enabled, Received optimization result. These are small in a terminal — box them or zoom.
  • Chapter markers: 00:00 Intro · ~01:00 dbt · ~07:00 Airflow · ~13:30 Wrap-up. Put them in the description too.
  • Secret scrub: scan every terminal frame for the API key, the .env file contents, any profiles.yml with a real key. Blur or re-cut.
  • Captions — auto-generate, then fix "Rabbit", "BigQuery", "dbt", "Composer", reservation IDs.
  • Thumbnail: the off→on log-line diff, or the dashboard savings number.
  • Description with links: dbt-rabbit-samples repo, rabbit-sample-dags repo, the dbt adapter and Airflow plugin READMEs, api-keys.
  • Publish target: unlisted first, share with one colleague for a review pass, then move to the customer-facing library.
